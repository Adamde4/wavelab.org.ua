# Wave — рішення для бізнесу

Односторінковий сайт-візитка для презентації послуг з розробки сайтів.
Повністю статичний (HTML/CSS/JS, без збірки та без бекенду) — готовий до розміщення на **GitHub Pages**.

## Структура проєкту

```
wave/
├── index.html          — головна сторінка (вся розмітка й SEO-теги)
├── 404.html            — сторінка "не знайдено" для GitHub Pages
├── robots.txt
├── sitemap.xml
├── css/
│   └── styles.css      — усі стилі й анімації
├── js/
│   ├── data.js              — масиви послуг (SERVICES) і портфоліо (PROJECTS)
│   ├── telegram-config.js   — токен бота і chat_id для форми заявок
│   ├── lead-form.js         — відправка форми заявки в Telegram
│   └── main.js               — меню, скрол-анімації, hover-ефекти, рендер карток
└── assets/
    ├── favicon.svg
    └── og-cover.svg     — картинка для прев'ю у соцмережах
```

## Форма заявки → Telegram

Форма в секції "Замовлення" відправляє заявки напряму в Telegram через бота
**@wave_site_bot**, без будь-якого бекенду.

**Обов'язковий крок перед запуском** — вказати, куди боту надсилати повідомлення:

1. Відкрийте `js/telegram-config.js`.
2. Напишіть боту [@wave_site_bot](https://t.me/wave_site_bot) і натисніть **Запустити**.
3. Перейдіть у браузері за посиланням (підставивши реальний токен бота):
   `https://api.telegram.org/bot8604036236:AAFheEtKI9AMSyzGU8Cfm_2aw2ui1ni3XzI/getUpdates`
4. У відповіді знайдіть `"chat":{"id": ЧИСЛО, ...}` і вставте це число замість
   `"YOUR_CHAT_ID"` у `js/telegram-config.js`.
5. Збережіть файл і опублікуйте зміни — форма одразу запрацює.

Поки `chat_id` не вказано, форма показує повідомлення про це замість помилки —
сайт при цьому не ламається.

⚠️ **Про безпеку.** Оскільки сайт статичний (без сервера), токен бота видно
у вихідному коді сторінки. Для простої форми заявок це прийнятний компроміс,
але якщо потрібна вища безпека — перенесіть відправку на невеликий
serverless-проксі (Cloudflare Worker / Netlify Function), який ховає токен
на сервері; сайт тоді звертається лише до цього проксі. Детальніший коментар —
на початку файлу `js/telegram-config.js`.

## Публікація через GitHub Pages

1. Створіть новий репозиторій на GitHub і завантажте туди вміст цієї папки
   (файли мають лежати в корені репозиторію, а не у вкладеній папці).
2. У репозиторії відкрийте **Settings → Pages**.
3. У полі **Source** оберіть гілку `main` і папку `/root`, натисніть **Save**.
4. Через кілька хвилин сайт буде доступний за адресою
   `https://<ваш-логін>.github.io/<назва-репозиторію>/`.

Усі шляхи до ресурсів (`/css/...`, `/js/...`, `/assets/...`) — абсолютні від кореня домену.
Якщо сайт публікується не в кореневому репозиторії користувача
(`<логін>.github.io`), а в проєктному репозиторії
(`<логін>.github.io/<репозиторій>/`), і ви **не** підключаєте власний домен —
замініть на початку шляхів `/css`, `/js`, `/assets` на відносні `./css`, `./js`, `./assets`
у `index.html` і `404.html`, або одразу підключіть власний домен (крок нижче) —
тоді абсолютні шляхи `/…` працюватимуть коректно без змін.

## Підключення власного домену

1. У корені репозиторію створіть файл `CNAME` (без розширення) з одним рядком —
   вашим доменом, наприклад:
   ```
   wave-studio.com
   ```
2. У панелі керування DNS вашого домену додайте записи:

   **Якщо домен кореневий (wave-studio.com):**
   | Тип | Ім'я | Значення |
   |---|---|---|
   | A | @ | 185.199.108.153 |
   | A | @ | 185.199.109.153 |
   | A | @ | 185.199.110.153 |
   | A | @ | 185.199.111.153 |

   **Якщо піддомен (www.wave-studio.com):**
   | Тип | Ім'я | Значення |
   |---|---|---|
   | CNAME | www | `<ваш-логін>.github.io` |

3. У **Settings → Pages** введіть домен у поле **Custom domain** і після перевірки DNS
   увімкніть **Enforce HTTPS**.
4. DNS-записи можуть застосовуватись до 24 годин.

Після підключення домену оновіть у `index.html`:
- `<link rel="canonical" ...>`
- `og:url`
- `robots.txt` (рядок `Sitemap:`)
- `sitemap.xml` (`<loc>`)

замінивши `https://example.com/` на ваш реальний домен.

## Google Analytics / Google Ads

- У `index.html` є закоментований блок **Google tag (gtag.js)** у `<head>` —
  розкоментуйте його та вставте свій ID вимірювання (`G-XXXXXXXXXX`), щоб увімкнути аналітику.
- `js/main.js` вже надсилає події конверсій через `gtag`, коли він підключений:
  - `telegram_click` — клік по будь-якому посиланню на Telegram;
  - `cta_discuss_project_click` — клік по кнопці "Обговорити проєкт" / "Написати в Telegram".
- Для Google Ads створіть у Google Ads / GA4 конверсію на основі цих подій —
  додаткового коду на сайті для цього не потрібно.

## Технічні примітки

- Без збірки: відкрийте `index.html` у браузері локально, або підніміть будь-який
  статичний сервер (`npx serve .`), щоб абсолютні шляхи `/css`, `/js` працювали коректно.
- Шрифти (Unbounded — заголовки, Manrope — основний текст, JetBrains Mono — лейбли
  й лічильники) підключені через Google Fonts CDN.
- Анімації:
  - вхідна послідовність hero-блоку при завантаженні сторінки (заголовок, текст,
    кнопки, статистика зʼявляються з затримкою одне за одним);
  - "промальовування" хвилі під заголовком (stroke-dasharray/dashoffset);
  - магнітні кнопки — злегка тягнуться до курсору при наведенні (`data-magnetic`);
  - легкий parallax світіння у hero-секції за рухом курсору;
  - скрол-анімації секцій на `IntersectionObserver` і hover-ефекти карток.
  - усе враховує `prefers-reduced-motion` і вимикається для людей, які просять менше руху.
- Сайт не використовує серверний код і повністю сумісний із GitHub Pages.
